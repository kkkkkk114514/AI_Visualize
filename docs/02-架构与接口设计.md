# 02 · 架构与接口设计

> 状态：**定稿 v1**（2026-09-20）。本文档中的图 IR、REST、WS、存储 schema 均为**契约**，改动需先改本文档再改代码。

## 1. 总体架构

```
浏览器（React SPA，Vite 构建）
 ├ 页面：模型库 / 工作台（/lab/:graphId[?run=…]）
 ├ 面板：图编辑器(xyflow) · 决策边界画布 · 网格世界画布
 ├ 渲染：uPlot 曲线 · canvas 数值渲染器（特征图/注意力/热力图/直方图，实时与回放共用）
 └ REST + WebSocket
        ↓
本地服务进程（Python + FastAPI + uvicorn，端口 8410）
 ├ Graph Service   IR 校验 · dry-run 形状推导 · GraphModule 构建
 ├ Runner Manager  run 生命周期 · 子进程管理 · 控制队列 · 看门狗
 ├ Probe Service   hook 采样 · 降采样量化 · 快照编码落盘
 ├ Run Store       SQLite（runs/metrics/snapshots）+ 文件（快照/权重）
 ├ Dataset Service 内置数据集下载缓存 · 上传解析 · DataLoader 构造
 ├ WS Hub          事件广播（按 run 订阅）
 └ Static          生产模式托管前端构建产物（单端口交付）
        ↓ multiprocessing（spawn）
训练 / 计算子进程（每 run 一个，可被强制终止）
 ├ TorchRunner     图 IR → GraphModule → 训练循环 + 探针
 ├ SklearnRunner   经典监督模型（自实现 step 级迭代训练，供边界演进可视化）
 └ TabularRLRunner GridWorld + 表格 Q-learning
```

### 关键决策（ADR 摘要）

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 训练在**独立子进程**（spawn），主进程不跑训练 | 崩溃隔离、可强杀、绕开 GIL；事件负载小，IPC 开销可接受 |
| D2 | **图 IR 为唯一真源**：预置模型 = 序列化的 IR，编辑器编辑 IR | 架构图与编辑器天然同源，不会出现两套不一致的数据结构 |
| D3 | 形状推导用**真实 dry-run**，不写规则表 | 与实际前向永远一致；参数量、报错信息都是真的 |
| D4 | **不做源码生成**，实现通用 `GraphModule`（拓扑执行器） | v1 无代码模式，无需生成 Python 源码；探针挂 hook 更容易 |
| D5 | 快照统一为「量化数值数组 + 前端 canvas 渲染」 | 实时与回放同一渲染路径；无 matplotlib 依赖；支持 hover 与 colormap |
| D6 | WS **只做服务端推送**，所有命令走 REST | 协议简单、易调试、命令可幂等重试 |
| D7 | ML / RL 与 DL 共用 run 生命周期、WS 事件与存储，仅 Runner 实现不同 | 界面、历史、回放全部复用一套设施 |
| D8 | 训练事件里的文案只传 **i18n key + 参数** | 双语翻译只在前端维护一份 |

## 2. 进程与并发模型

- **主进程**（uvicorn）：处理 REST / WS / dry-run（dry-run 在短生命周期线程池中执行，避免阻塞事件循环）。
- **每 run 一个子进程**：`multiprocessing.get_context("spawn")`（Windows 必需；子进程入口为模块级函数，不依赖 fork 语义）。
- **通信**：
  - 子进程 → 主进程：`event_queue`（`multiprocessing.Queue`），元素为纯 dict（仅基本类型，便于序列化）。
  - 主进程 → 子进程：`control_queue`，子进程在**每个 batch 边界**非阻塞 drain；`pause` 时进入 100ms 轮询睡眠。
- **主进程内的桥接**：每 run 一个 reader 线程执行 `queue.get()`，通过 `loop.call_soon_threadsafe` 投递到 asyncio 层，再分发到 WS Hub 与 Run Store。
- **写库节流**：指标先在内存聚合，每 2s 或累计 200 行批量写入 SQLite；run 结束 / 异常时强制 flush。
- **并发约束**：同时最多 1 个活动 run（`Runner Manager` 强制）；历史 run 的数据读取无限制。

## 3. 图 IR 规范（深度学习模型）

### 3.1 结构

```json
{
  "ir_version": 1,
  "id": "cnn-mnist",
  "kind": "dl",
  "name": { "zh": "CNN 手写数字分类", "en": "CNN Digit Classifier" },
  "desc": { "zh": "两层卷积 + 全连接", "en": "Two conv layers + FC head" },
  "task": "image_classification",
  "hyper_defaults": {
    "optimizer": "adam", "lr": 0.001, "batch_size": 64,
    "epochs": 5, "loss": "cross_entropy"
  },
  "probe_defaults": ["conv1", "conv2"],
  "nodes": [
    { "id": "input",  "type": "Input",    "params": { "shape": [1, 28, 28] }, "ui": { "x": 0, "y": 120 } },
    { "id": "conv1",  "type": "Conv2d",   "params": { "out_channels": 16, "kernel_size": 3, "stride": 1, "padding": 1 }, "ui": { "x": 220, "y": 100 } },
    { "id": "relu1",  "type": "Activation","params": { "name": "relu" }, "ui": { "x": 440, "y": 120 } },
    { "id": "pool1",  "type": "MaxPool2d","params": { "kernel_size": 2 }, "ui": { "x": 660, "y": 120 } },
    { "id": "flat",   "type": "Flatten",  "params": {}, "ui": { "x": 880, "y": 120 } },
    { "id": "fc1",    "type": "Linear",   "params": { "out_features": 128 }, "ui": { "x": 1100, "y": 120 } },
    { "id": "relu2",  "type": "Activation","params": { "name": "relu" }, "ui": { "x": 1320, "y": 120 } },
    { "id": "head",   "type": "Linear",   "params": { "out_features": 10 }, "ui": { "x": 1540, "y": 120 } },
    { "id": "output", "type": "Output",   "params": { "classes": 10 }, "ui": { "x": 1760, "y": 120 } }
  ],
  "edges": [
    { "id": "e1", "source": "input", "source_port": "out", "target": "conv1",  "target_port": "in" },
    { "id": "e2", "source": "conv1", "source_port": "out", "target": "relu1",  "target_port": "in" },
    { "id": "e3", "source": "relu1", "source_port": "out", "target": "pool1",  "target_port": "in" },
    { "id": "e4", "source": "pool1", "source_port": "out", "target": "flat",   "target_port": "in" },
    { "id": "e5", "source": "flat",  "source_port": "out", "target": "fc1",    "target_port": "in" },
    { "id": "e6", "source": "fc1",   "source_port": "out", "target": "relu2",  "target_port": "in" },
    { "id": "e7", "source": "relu2", "source_port": "out", "target": "head",   "target_port": "in" },
    { "id": "e8", "source": "head",  "source_port": "out", "target": "output", "target_port": "in" }
  ]
}
```

- `nodes[].params` 只放**结构参数**；`ui` 只放画布坐标，后端忽略（**形状缓存 key 也忽略 `ui`**，拖动节点不触发重算）。
- `id` 由前端生成（短随机串，如 `n7k2`）；预置模型使用稳定 id（探针默认值、回放都依赖它）。
- 名称字段使用 `{zh, en}`；非双语内容（如用户自建节点名）允许纯字符串，前端兜底显示。
- 预置可带顶层 `dataset_id`（如 `"xiyouji"`）：新建实验时前端据此默认选中数据集与配套超参（仅默认值，用户可改；后端 `parse_graph` 忽略该字段，训练时以请求里的 `dataset_id` 为准）。
- 存储位置：预置模型放在 `backend/app/graph/presets/*.json`（随代码走）；用户自建模型存入 SQLite `models` 表。

### 3.2 节点白名单（v1）

| type | 参数 | 形状语义 |
| --- | --- | --- |
| `Input` | `shape`（来自数据集，UI 只读） | 图起点；dtype 由 `task` 决定：图像/表格 = float32，文本/序列 = long（词 id） |
| `Linear` | `out_features`, `bias=true` | `(*, in) → (*, out)` |
| `Conv2d` | `out_channels`, `kernel_size`, `stride`, `padding`, `dilation=1`, `groups=1` | `(B,C,H,W) → (B,C',H',W')` |
| `MaxPool2d` / `AvgPool2d` | `kernel_size`, `stride=null→kernel`, `padding` | 空间下采样 |
| `AdaptiveAvgPool2d` | `output_size` | 输出固定尺寸（CNN 收尾） |
| `Flatten` | `start_dim=1` | `(B,C,H,W) → (B,C·H·W)` |
| `Dropout` | `p` | 逐元素随机置零（仅训练态） |
| `Activation` | `name ∈ {relu, leaky_relu, gelu, tanh, sigmoid}` | 逐元素 |
| `BatchNorm2d` / `BatchNorm1d` | `eps=1e-5`, `momentum=0.1` | 通道/特征维归一化 |
| `LayerNorm` | `normalized_shape`（默认从输入推断） | 最后一维归一化 |
| `Embedding` | `num_embeddings`（= 词表大小，来自数据集）, `embedding_dim` | `(B,T) → (B,T,D)` |
| `PositionalEncoding` | `max_len`, `mode ∈ {learned, sinusoidal}` | `(B,T,D) → (B,T,D)` |
| `LSTM` | `hidden_size`, `num_layers=1`, `bidirectional=false`, `return_sequences=true` | `(B,T,D) → (B,T,H)` |
| `MultiHeadAttention` | `num_heads`, `causal=true`, `dropout=0` | `(B,T,D) → (B,T,D)`（`D` 由输入推断） |
| `ResidualAdd` | — | 两个相同形状输入相加（多输入端口） |
| `Concat` | `dim` | 除 `dim` 外形状相同 |
| `Output` | `classes`（分类）/ `out_dim`（回归） | 图终点，**声明式校验**：入端最后一维必须等于该值（不做投影；分类头由上游 `Linear` 承担）；softmax 由损失函数负责 |

### 3.3 端口与连线规则

- 单入单出节点：端口名固定 `in` / `out`。
- 多输入节点（`ResidualAdd` / `Concat`）：端口 `in1..inN`，随连线自动扩展，上限 4。
- 图必须是 **DAG**；节点出度可 > 1（fan-out 复制张量）；入度遵循各节点定义（默认 1）。
- 必须恰好 1 个 `Input` 与 1 个 `Output`（v1 约束，简化校验与 dry-run）。
- 形状一致性的最终裁决权在 dry-run（D3）：dry-run 失败时把底层报错的节点 id 映射回 IR，生成可读信息。

### 3.4 数据集绑定（`ir.bind_dataset`）

在 dry-run 与训练启动前，按 `dataset_id` 把「由数据集决定」的节点参数写进 IR 的**运行时副本**（不修改用户保存的图）；绑定规则固定如下：

| 位置 | 绑定字段 | 来源 |
| --- | --- | --- |
| `Input` | `shape` | 数据集 `input_shape`（batch 维由运行时决定） |
| `Output` | `classes` | 数据集 `num_classes`（分类任务） |
| `Embedding` | `num_embeddings` | 数据集 `vocab_size`（文本任务） |
| **直连 `Output` 的 `Linear`** | `out_features` | 数据集 `num_classes` |

- 最后一条解决「分类头开箱可用」：上游 `Linear` 的 `out_features` 常被用户随手填错，只要它**出端口直接连到 `Output`**，就以数据集类别数为准覆盖（文本 LM 场景下 `num_classes = vocab_size`，同一规则同时服务分类与字符级语言模型）。非直连的 `Linear` 不受影响。
- 绑定后仍走 dry-run 校验：若与 `Output.classes` 声明冲突（如中间层形状推不通），照常在对应节点报错。

## 4. 形状推导（dry-run）与 GraphModule

### 4.1 dry-run

- dummy 输入按 `task` 生成：图像 `(2, C, H, W)`；序列 `(2, T)`（`T` 取数据集默认长度，如 32）；表格/回归 `(2, F)`。`C/H/W/T/F` 一律来自数据集元数据；**M1 阶段先从 `Input` 节点的 `shape` 取**（batch 固定 2），接入数据集后由数据集元数据覆盖。
- dtype：图像/表格 = `float32`；文本/序列（`task` 含 `text`/`language`）= `int64` 词 id。
- 流程：IR → `GraphModule` → `register_forward_hook`（逐节点）→ 前向 → 收集。
- **失败即停**：出错节点作为当前节点记录，后续节点无结果（前端只标红该节点）；`Output` 的声明维不匹配、通道数/维度不符等都在此定位到节点。
- 多输入节点（`ResidualAdd` / `Concat`）返回 `in_shapes`（数组）；单输入节点返回 `in_shape`。两者都带 `out_shape` 与 `params`（该节点可训练参数量，未执行的节点为 `null`）。
- 返回：

```json
{
  "ok": false,
  "nodes": { "conv1": { "in_shape": [2,1,28,28], "out_shape": [2,16,28,28], "params": 160 } },
  "total_params": 123456,
  "errors": [ { "node_id": "fc1", "code": "shape_mismatch", "message": "Linear 期望最后一维 4608，实际为 3200" } ]
}
```

- 缓存：按 `hash(graph_ir) + dataset_id` 缓存结果（LRU 64），重复连线不重复 dry-run；单次 dry-run 目标 < 300ms（小模型）。

### 4.2 GraphModule

- 通用拓扑执行器，不做源码生成：

```python
class GraphModule(nn.Module):
    """nodes: {node_id: nn.Module}（注册为合法子模块名），order: 拓扑序，edges: fan-in 映射"""
    def forward(self, x):
        outs = {}
        for node_id in self.order:
            inputs = [outs[e.source] for e in self.fan_in[node_id]]
            outs[node_id] = self._nodes[node_id](*inputs) if len(inputs) > 1 else self._nodes[node_id](inputs[0])
        return outs[self.output_id]
```

- 子模块名使用 `n_<id>`；保证 `state_dict`、hook、探针路径稳定（回放时按同名层取快照）。
- 主进程 dry-run 与子进程训练**共用同一实现**，避免"推导的形状"与"训练时的形状"不一致。

## 5. run 生命周期与控制

### 5.1 状态机

```
created → running ⇄ paused → finished
                    ↘ stopped / failed / interrupted
```

| 状态 | 含义 |
| --- | --- |
| `created` | 记录已建，子进程启动中 |
| `running` | 正常训练 |
| `paused` | 在 batch 边界暂停（子进程存活，100ms 轮询控制队列） |
| `finished` | 跑完设定 epoch |
| `stopped` | 用户停止（优雅退出） |
| `failed` | 异常退出（附错误信息） |
| `interrupted` | 服务重启导致的孤儿 run（启动时统一标记） |

### 5.2 控制命令（REST → control_queue）

| action | 生效时机 | 语义 |
| --- | --- | --- |
| `pause` | 当前 batch 后 | 停止取下一批，推 `run.status=paused` |
| `resume` | 立即 | 继续训练 |
| `stop` | 当前 batch 后 | 保存最优权重、flush 指标后退出 |
| `kill` | 立即 | 子进程 `terminate()`（UI 的"停止"先发 `stop`，3s 未退出再发 `kill`） |
| `set_lr` | 下一 step | 写入 `optimizer.param_groups`，同时记入 metrics（曲线可见） |
| `set_batch_size` | 下一 epoch | 重建 DataLoader |

### 5.3 看门狗与异常

- 主进程记录 `last_event_at`：`running` 状态超过 `max(30s, 3 × 该 run 平均 epoch 耗时)` 无任何事件 → 推 `error(code=stale)` 提示但**不自动杀**（避免误杀慢 epoch）。
- 子进程退出码非 0 或异常信息随事件回传 → `failed` + 可读错误（`error` 事件带 i18n key 与原始 traceback 摘要）。
- 服务重启：启动时把所有 `running` / `paused` 的 run 标记为 `interrupted`，其快照与曲线仍可回放。

### 5.4 指标与采集时机

| 指标 | 采集时机 | 说明 |
| --- | --- | --- |
| `loss` | 每个 train step | 该 batch 的损失（不做 epoch 平均） |
| `acc` | 每个 train step | 该 batch 的准确率（分类任务；回归任务不发） |
| `val_loss` / `val_acc` | 每个 epoch 末 | 在完整 val 集上 `eval()` + `no_grad` 评估，评估后恢复 `train()`；挂在该 epoch 最后一个 step 上 |
| `lr` | 每个 step | `optimizer.param_groups[0]["lr"]`，`set_lr` 后下一个 step 立即反映 |
| `grad_norm` | 每个 step | **裁剪前**的全局梯度 L2 范数 |
| `throughput` | 每个 step | 近 20 step 滑动平均（samples/s） |
| `vram_mb` | 每 50 step | 仅 CUDA 设备；CPU 不发该指标 |

- 所有指标以全局 `step`（跨 epoch 累加，从 1 开始）为 x 轴。
- 子进程内先聚合，每 20 step 或每 1s 打包成**一条** `metrics` 事件（`points` 数组）再入队，降低 IPC 与 WS 压力；run 结束时强制发出剩余点。
- 主进程按 §2 的节流规则批量写库（2s / 200 行），`finished` / `stopped` / `failed` 时强制 flush。
- 梯度裁剪由超参 `grad_clip`（默认 5.0，0 = 关闭）控制；`grad_norm` 记录裁剪前的范数，因此曲线在裁剪生效时仍能看出真实幅值。
- **冷启动**：子进程首次 `import torch` 与首次构建 optimizer 在 CPU 机上合计约 2~5s（本机实测 torch 导入 ~1.8s、首个 Adam ~1.7s，之后为 0），这段时间 run 停在 `created`、前端显示"启动中"；子进程一进入 `run_training` 就先发 `log.run.starting`，界面据此确认已拉起。
- **CPU 线程数**：子进程入口执行 `torch.set_num_threads(config.TORCH_THREADS)`，默认 `max(1, min(8, cpu_count() // 2))`，可用 `AI_VISUALIZE_TORCH_THREADS` 覆盖。小批量（batch 64）下线程超订既拖慢训练又挤占浏览器渲染进程：本机实测（MNIST + MLP）torch 默认 16 线程 191 step/s、24 线程 124 step/s，而 8 / 6 / 4 线程分别为 219 / 256 / 288 step/s。

### 5.5 子进程 → 主进程事件（`event_queue` 元素）

全部为纯 dict（仅基本类型 + 数组），以 `type` 区分；字符串文案只带 i18n key（D8）。

| type | 字段 |
| --- | --- |
| `status` | `status`, `step`, `epoch`, `elapsed_s` |
| `metrics` | `points: [{step, epoch, values{…}}]` |
| `probe` | `snapshot_id`, `step`, `epoch`, `node_id`, `kind`, `shape`（M3 使用） |
| `log` | `level`, `key`, `args` |
| `error` | `code`, `message_key`, `args`, `node_id?`, `detail`（traceback 摘要） |
| `bye` | `exit_code`（reader 线程据此收尾） |

主进程 → 子进程（`control_queue`）只有控制命令：`{"action": …, "value": …}`（§5.2）。

> 队列内事件名是"内部协议"：`status` 广播到 WS 时改写为 `run.status`（§8.2 的线上名），其余类型原样透传。

## 6. 探针与快照

### 6.1 探针配置

探针目标在**创建 run 时确定**（训练中不改变 hook 集合），条目结构：

```json
{ "node_id": "conv1", "kind": "feature_grid", "every_n_steps": 50, "sample_index": 0, "max_items": 32 }
```

- `POST /api/runs` 的 `probes` 字段为上述对象的数组；缺省取模型 IR 的 `probe_defaults`（节点 id 列表，逐项按默认 kind / 频率展开）；两者都没有则不挂探针。
- `kind` 默认按节点类型推导：`Conv2d → feature_grid`、`MultiHeadAttention → attention`、`LSTM → hidden`、其余可前向节点（`Linear`/`Activation`/`BatchNorm*`/`LayerNorm` 等）→ `histogram`；任意有参数的节点可手动改为 `weights`（读参数快照，不参与前向）。
- 采样时机：全局 step（从 1 起）满足 `step % every_n_steps == 0` 时对该节点采样一次；`sample_index` 取批次内第几个样本（越界取最后一个）。
- **非采样步零开销**：forward hook 只在采样步的前向前注册、前向结束立即摘除；`weights` 类不依赖前向。`attention` 需要 `nn.MultiheadAttention` 返回注意力权重，节点实现按「本步是否采样」动态切换 `need_weights`。
- 采样上限：每个 `(node_id, kind)` 流最多 `PROBE_MAX_PER_STREAM = 200` 条快照；达到后停止该流并发一条 `log` 事件（`log.probe.capped`），避免长训练把磁盘写爆（容量见 §7.3）。
- 形状不匹配（如对 `Linear` 取 `feature_grid`）在子进程内发现：停用该流、发一条 `log` 事件（`log.probe.disabled`），不影响训练。
- 有探针的 run 在训练开始时发一条 `log.probe.attached`（`args.n` = 流数），无探针则完全静默。

### 6.2 降采样与编码

| kind | 降采样 | shape | dtype |
| --- | --- | --- | --- |
| `feature_grid` | 前 min(C, `max_items`, 32) 通道，每通道 avg-pool 至 ≤ 32×32 | `[C,H,W]` | uint8（min-max 归一） |
| `attention` | 前 min(heads, `max_items`, 8) 头，矩阵 strides 降采样至 ≤ 64×64 | `[heads,T,T]` | uint8（值域 [0,1]） |
| `hidden` | (T,H) 热力图两维 strides 降采样至 ≤ 64×64 | `[T,H]` | uint8 |
| `histogram` | 32 bins 等宽，范围取张量 [min, max]（`min == max` 时取 ±0.5） | `[bins]` | uint32（不归一） |
| `weights` | 同 feature_grid（按输出通道） | `[C,H,W]` | uint8 |

统一容器（`payload`）：

```json
{ "shape": [16,28,28], "dtype": "uint8", "layout": "CHW", "min": -1.23, "max": 4.56, "data_b64": "...", "meta": {} }
```

- `min` / `max` 为量化前的真实值域，前端用其还原真实数值（hover 显示原始量级）：`value = min + q / 255 * (max - min)`。
- `meta` 仅在需要时出现：`attention` 带 `{heads, tokens, causal}`，`histogram` 带 `{bins}`。
- 单快照默认 ≤ 64KB（base64 后）。

### 6.3 传输与存储

- 落盘：`data/runs/{run_id}/snapshots/{snapshot_id}.json`（即上节容器 + 元数据）+ `snapshots` 表行索引（§7.2）。
- 快照文件结构：

```json
{
  "id": "s_ab12cd34", "run_id": "r_2f9c", "step": 250, "epoch": 2,
  "node_id": "conv1", "kind": "feature_grid",
  "shape": [16,28,28], "dtype": "uint8", "layout": "CHW",
  "min": -3.12, "max": 4.87, "data_b64": "...",
  "meta": { "heads": 4, "tokens": 32, "causal": true },
  "created_at": "2026-09-20T21:04:11+08:00"
}
```

- WS 只推 `probe.snapshot` 元数据（id / step / epoch / node_id / kind / shape）；前端按需 `GET /api/runs/{id}/snapshots/{sid}` 拉取。
- **ETag**：快照一次写定、内容不可变，故 `ETag: "<snapshot_id>"` + `Cache-Control: public, max-age=31536000, immutable`；带 `If-None-Match` 命中返回 304。前端 `api/snapshots.ts` 按 id 缓存 payload 并对并发请求去重。
- **实时与回放共用同一条渲染与拉取路径**：实时跟随最新 id；回放按索引选择步（M3 提供步选择器，时间轴 slider 属 M4）。

## 7. 存储设计

### 7.1 目录布局

```
data/
  app.db
  datasets/
    {dataset_id}/raw/              # 下载缓存（官方压缩包原样存放）
    manual/                        # 手动导入区：网络受限时把官方压缩包放这里
  runs/{run_id}/
    snapshots/{snapshot_id}.json
    checkpoints/best.pt
```

- 文件查找顺序：`{dataset_id}/raw/` → `manual/` → `backend/app/datasets/corpora/`（随仓库分发的字符级语料，见 §7.4）；三处都按**文件 md5** 判定有效性（与 torchvision 官方一致），md5 不符的文件视为未缓存并在 UI 提示路径。
- 下载写入 `*.part` 临时文件，校验 md5 后改名（避免半包被当成缓存）；镜像列表可配置，逐个回退。

### 7.2 SQLite schema

```sql
CREATE TABLE models (               -- 用户自建模型（预置模型随代码走，不入库）
  id TEXT PRIMARY KEY, name TEXT NOT NULL, kind TEXT NOT NULL,
  graph_json TEXT, created_at TEXT, updated_at TEXT
);
CREATE TABLE runs (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, kind TEXT NOT NULL,   -- dl | ml | rl
  model_id TEXT, graph_json TEXT,                                 -- dl 存图；ml/rl 存参数
  dataset_id TEXT, hyperparams_json TEXT, probes_json TEXT,        -- 探针配置（§6.1），回放时据此列层
  status TEXT NOT NULL,
  device TEXT, seed INTEGER, created_at TEXT, started_at TEXT, finished_at TEXT,
  error TEXT, best_metric REAL, total_steps INTEGER
);
CREATE TABLE metrics (
  run_id TEXT NOT NULL, step INTEGER NOT NULL, epoch INTEGER,
  name TEXT NOT NULL, value REAL NOT NULL
);
CREATE INDEX idx_metrics_run_name_step ON metrics(run_id, name, step);

CREATE TABLE snapshots (
  id TEXT PRIMARY KEY, run_id TEXT NOT NULL, step INTEGER NOT NULL, epoch INTEGER,
  node_id TEXT, kind TEXT NOT NULL, shape_json TEXT,
  min REAL, max REAL, file_path TEXT NOT NULL, created_at TEXT
);
CREATE INDEX idx_snapshots_run_step ON snapshots(run_id, step);
```

- `metrics` 采用长表（name/value）以容纳不同算法的指标集合；读取时服务端做 LTTB 降采样（`max_points` 默认 2000）。
- `runs` 的 schema 演进用**启动期轻量迁移**（`PRAGMA table_info` 检查缺列后 `ALTER TABLE ADD COLUMN`）——M3 新增 `probes_json`，老库自动补列。
- `runs.total_steps` / `best_metric` 随训练更新：与指标写库同一节流节拍（2s）更新一次，避免高频写 run 行。
- 删除 run：先删文件目录，再删 DB 行（单事务）；"清理全部历史"批量执行。

### 7.3 容量估算（默认配置）

| 项 | 估算 |
| --- | --- |
| metrics | 10k step × 8 指标 ≈ 80k 行 ≈ 3MB |
| snapshots | 200 × ~40KB ≈ 8MB |
| checkpoint | 只存最优 1 份，取决于模型（小模型数 MB） |
| **单 run 合计** | **< 30MB**（约束上限 100MB） |

### 7.4 字符级语料（随仓库分发）

`backend/app/datasets/corpora/` 存 M3 的中/英字符级语料，`DatasetSpec.loader = "text_char"` 的数据集直接引用它们（`corpus` 字段），因此**永远处于"已缓存"状态、无需下载**（公版文本，来源与许可见同目录 `README.md`）：

| dataset_id | 语料 | 词表 |
| --- | --- | --- |
| `alice` | Project Gutenberg #11《爱丽丝梦游仙境》（英） | 全部字符 + `<unk>` = 76 |
| `xiyouji` | 中文维基文库《西遊記》第 1–30 回（繁体） | 高频 1023 字 + `<unk>` = 1024 |

- 分词：`Counter` 统计词频，超过 `vocab_cap` 时保留最高频的 `vocab_cap - 1` 个字符，其余映射到 idx 0 `<unk>`；不足上限时按字符序全量保留（均含 `<unk>`）。词表由（语料, 上限）唯一决定，`registry.meta()` 的 `vocab_size` / `num_classes` 都取自它。
- 切分：前 90% 为训练、后 10% 为验证（在**字符序列**上切，杜绝窗口跨界泄漏）；窗口 `x = ids[i:i+T]`、`y = ids[i+1:i+T+1]`，`stride = T` 不重叠，`T = 32`。`train_size` / `val_size` 对文本按**窗口数**生效（0 = 全部）。
- 文本任务 `task = "text_lm"`：`Input.shape = [T]`、dtype int64，`num_classes = vocab_size`，于是 `Output.classes` 与直连 Output 的 `Linear.out_features` 都由词表绑定（§3.4），配合 `CrossEntropyLoss` 直接做下一字符预测。

### 8.3 创建 run 的请求体（POST /api/runs）

```json
{
  "model_id": "mlp-mnist",
  "graph": null,
  "dataset_id": "mnist",
  "name": "MLP 手写数字 · 14:32",
  "seed": 42,
  "hyperparams": {
    "optimizer": "adam", "lr": 0.001, "batch_size": 64, "epochs": 5,
    "loss": "cross_entropy", "grad_clip": 5.0, "train_size": 20000, "val_size": 5000
  },
  "probes": [
    { "node_id": "conv1", "kind": "feature_grid", "every_n_steps": 50 }
  ]
}
```

- `model_id` 与 `graph` 二选一：`model_id` 从预置（或 `models` 表）取图；`graph` 为内联图 IR（编辑器"未保存直接训练"）。两者都缺 → 400 `errors.run.needModel`。
- `dataset_id` 必填（v1 只有 DL 训练路径）；`name` 缺省按「模型显示名 + 本地时间」生成；`seed` 缺省 42。
- `hyperparams` 缺项按「模型 `hyper_defaults` → 全局默认」兜底；全局默认 `optimizer=adam`、`lr=0.001`、`batch_size=64`、`epochs=3`、`loss=cross_entropy`、`grad_clip=5.0`、`train_size=20000`、`val_size=5000`。
- `optimizer ∈ {adam, adamw, sgd}`；`loss ∈ {cross_entropy, mse}`（mse 用于 `out_dim > 0` 的回归头）；`train_size` / `val_size` 为 `0` 表示用完整数据集（CPU 默认各取 2 万 / 5 千以控制单 epoch 耗时）。
- `probes` 为探针条目数组（§6.1）：`node_id` 必须在图中存在、`kind` 在允许集合内、`every_n_steps ≥ 1`；缺省用图的 `probe_defaults` 展开，解析后的结果原样存入 `runs.probes_json` 并随 run 详情返回，供回放列层。
- 超参越界（如 `lr ≤ 0`、`epochs` 不在 1..50）→ 422 `errors.run.invalidHyper`（`args.param` 指出字段）。
- 数据集未缓存 → 409 `errors.dataset.notCached`（`args.path` 给出应放置的目录，前端据此引导下载/手动导入）。
- 已存在活动 run（`created` / `running` / `paused`）→ 409 `errors.run.busy`（`args.run_id` 给出占用者）。
- 成功 → 201 `{ "run": {…} }`（结构同 `GET /api/runs/{id}`）。

### 8.4 状态码与错误码对照

| HTTP | code | 场景 |
| --- | --- | --- |
| 400 | `errors.run.needModel` | `model_id` 与 `graph` 都没给 |
| 404 | `errors.run.notFound` / `errors.model.notFound` / `errors.dataset.notFound` | 资源不存在 |
| 409 | `errors.run.busy` | 同时只允许 1 个活动 run（FR-5） |
| 409 | `errors.dataset.notCached` | 数据集未缓存，需先下载或手动导入 |
| 409 | `errors.dataset.downloading` | 该数据集已在下载中（幂等去重） |
| 409 | `errors.run.notActive` | 对已结束的 run 发控制命令 |
| 409 | `errors.run.conflict` | 控制命令与当前状态冲突（如未在暂停态发 `resume` 之外的非法跃迁） |
| 422 | `invalid_ir` / `errors.run.invalidHyper` | 图结构错误（体同 `/api/graph/validate`）/ 超参越界 |
| 422 | `invalid_probe` | 探针配置非法（`node_id` 不在图中 / `kind` 非法 / 频率越界），`message_key` 为 `errors.probe.*` |
| 500 | `errors.run.spawnFailed` | 子进程启动失败 |

### 8.5 停止与强制终止

- `POST /api/runs/{id}/control {action:"stop"}`：主进程只入队，等子进程自然收尾（flush 指标、存最优权重）。
- 3s（`RUN_STOP_GRACE_S`）内未退出 → 主进程 `terminate()`；再过 1s 仍未退出 → `kill()`；子进程退出后 run 一律落库为 `stopped`（用户意图优先，不因退出码非 0 记 `failed`）。
- 服务关闭（lifespan 收尾）对活动 run 执行同样流程，避免留下孤儿进程。

### 8.2 WS 协议

客户端 → 服务端（仅订阅与心跳）：

```json
{ "type": "subscribe",   "run_id": "r_2f9c" }
{ "type": "unsubscribe", "run_id": "r_2f9c" }
{ "type": "pong" }
```

服务端 → 客户端：

| type | payload 要点 |
| --- | --- |
| `run.status` | run_id, status, step, epoch, device, elapsed_s（终态另带 best_metric、exit_code） |
| `metrics` | run_id, points: [{step, epoch, values{loss, acc, val_loss, val_acc, lr, grad_norm, throughput, vram_mb}}] |
| `probe.snapshot` | run_id, snapshot_id, step, epoch, node_id, kind, shape |
| `dataset.progress` | dataset_id, phase, progress(0..1) |
| `log` | run_id, level, key, args（**只发 i18n key + 参数**，双语文案在前端） |
| `error` | run_id?, code, message_key, args, node_id? |
| `run.deleted` | run_id（run 被删除后刷新列表） |

- 订阅语义：带 `run_id` 的事件只推给发过 `subscribe` 的连接（同一 run 可多端同时订阅）；不带 `run_id` 的（`dataset.progress`、`run.deleted`）广播给全部连接。

- 心跳：服务端每 20s 推 `{"type":"ping"}`；客户端断线后指数退避重连，重连成功先用 REST 拉全量状态补齐（不依赖事件重放）。

## 9. 前端架构

### 9.1 目录与职责

```
frontend/src/
  api/          rest.ts · graph.ts · runs.ts · snapshots.ts（按 id 缓存 + ETag 304）· datasets.ts · ws.ts（单例，重连/订阅管理）· types.ts（与本文档契约一致）
  i18n/         index.ts · locales/{zh-CN,en}.json
  pages/        LibraryPage（模型库）· LabPage（工作台 + 回放模式）
  panels/       GraphEditor/ · TrainingConfig/ · MetricsCharts/ · RunList/ · RunControls/
                （registry.ts / ProbeViewer/ 于 M3 引入）
  panels/ml/    DecisionBoundaryCanvas · ModelConfigForm
  panels/rl/    GridWorldCanvas · RLConfigForm
  renderers/    HeatmapCanvas · FeatureGridCanvas · HistogramCanvas（数值数组 → canvas 的统一渲染层）
  stores/       graphStore · runStore · uiStore · i18nStore（zustand）
  graph/        ir.ts（类型与构造）· validate.ts（本地预校验）· layout.ts（自动布局）
```

### 9.2 关键机制

- **面板注册表**：`panelRegistry[kind] = PanelSpec[]`，工作台按模型类型装配左 / 中 / 右三区；新增算法只注册面板，不改外壳。
- **路由**：`/` 模型库；`/lab/:graphId` 新建实验；`/lab/:graphId?run=r_xxxx` 回放历史 run（同一页面，不同数据源）。
- **状态管理**：zustand + 不可变更新；WS 事件统一在 `api/ws.ts` 分发给监听者（`runStore.bindRunEvents` 落地）；run 的标量状态（status / step / epoch / 耗时 / 日志）进 zustand，**指标点进 `runStore` 导出的 `metricsBuffer` 单例环形缓冲**（不参与 React 渲染），历史/回放按需用 `GET /api/runs/{id}/metrics` 拉齐。
- **曲线性能**：uPlot 直接操作 DOM（绕过 React 渲染），数据 push 采用环形缓冲；主图 loss / val_loss + 右轴 acc / val_acc 默认显示，**点击图例项即可单独隐藏 / 恢复该曲线**（隐藏项在图例里收成一个暗色标签，只保留名字便于点回；⌘/Ctrl + 点击 = 只看该曲线），lr / grad_norm / throughput 勾选后各占一张小图（量级不同，不共用 y 轴），val_* 点同时充当 epoch 分界线。
- **只读预置可直接训练**：预置图不可编辑但可训练（POST `/api/runs` 带 `model_id`，后端从磁盘读预置）；编辑需先「克隆为副本」。
- **探针渲染**：React 只管理容器与控件，像素级绘制在 `renderers/*` 的 canvas 中完成；切换 colormap / hover 不触发 React 重渲染。
- **撤销重做**：图编辑维护独立历史栈（基于 IR 快照 diff，上限 50 步），只对图编辑生效。
- **i18n**：默认语言取 `navigator.language`，回退 `zh-CN`；切换持久化到 localStorage；模型名/说明按 `{zh, en}` 取当前语言。
- **图编辑器交互**：连线后 300ms 防抖调用 `/api/graph/infer`，把形状写回节点徽标；本地 `validate.ts` 先做结构性预校验（环路、悬空端口、缺 Input/Output），形状级校验交给后端。本地与后端同一规则：**已有结构性错误时不再做环路/可达性推导**，避免同一根因刷出多条派生提示。
- **节点的两种加入方式**：①从左侧节点面板**拖拽**到画布，在落点创建；②在画布空白处**右键**弹出按分组排列的选型菜单，点选后在右键处创建，**再次右键空白处即取消**（Esc、左键点空白、缩放平移也会关闭）。单击面板项不再创建节点；只读模式下拖拽与右键菜单均禁用。
- **画布平移**：右键被选型菜单占用（xyflow 在 `panOnDrag` 含 2 时不会派发 `onPaneContextMenu`），因此平移只保留中键拖拽、空格 + 左键拖拽与触控板双指滚动。
- **右侧节点说明栏**：按分组列出全部节点的作用（`nodes.desc.*`，中英双语），画布上选中的节点对应条目高亮，供编辑者随时对照节点语义。
- **只读与克隆**：预置图以只读打开（节点参数与连线均不可改），画布结构签名不变时不会重复请求后端；「克隆为副本」仅更换模型 id 并解除只读，节点 id 与 `name` / `desc` / 探针配置原样保留，原预置不受影响。整图被替换（打开 / 克隆）时前端自增 `epoch` 强制重新推导，避免"签名未变 → 结果被清空却不重算"的空窗。
- **工作台布局（M3）**：顶部 `run-bar` 常驻训练控制（启动 / 暂停·恢复 / 停止、状态徽标、step·epoch、耗时、设备）；左侧竖分「节点面板 + 训练配置」，中间竖分「图编辑器 + 训练曲线 + 探针」，右侧竖分「检查与提示 + 节点说明 + 历史 run」。训练进行中「训练配置」的 dataset / optimizer / epochs / loss 锁为只读，**仅 lr 与 batch size 可改**（分别下一 step / 下一 epoch 生效），与 §5.2 的控制命令一一对应。
- **探针面板（M3）**：训练配置面板内提供**探针层勾选**（按 `(node_id, kind)` 列出图中可探针的层，勾选状态随 run 启动提交；全不勾 = 无探针，便于对照吞吐）；探针面板顶部按当前选中的 `(node_id, kind)` 流切换渲染器（特征图 / 注意力矩阵 / 直方图 / 权重），并支持 colormap 切换。面板展示的 run **以快照索引所属的 run 为准**（`runStore.snapshotRunId`）：实时 = 已挂/刚启动的 run，回看 = 列表里选中的历史 run；流列表、步选择器、快照 payload 三者同源，避免「已挂 run A + 回看 run B」时跨 run 取快照。数据统一走 `api/snapshots.ts`：`GET` 快照详情（按 `snapshot_id` 缓存 + `If-None-Match` 复用 304），**实时与回放同一渲染 / 取数路径**（实时只跟随最新采样步，回放用步选择器；完整时间轴滑块属 M4）。hover 读数由 payload 的 `min/max` 反量化回**量化前真实值**，像素绘制在 canvas 中完成、不触发 React 重渲染。
- **实时曲线**：`loss` / `acc`（含 `val_*`）默认显示、图例项可点击隐藏 / 恢复（`u-off` 行为 uPlot 原生，隐藏后图例只留暗色标签，点回即恢复），`lr` / `grad_norm` / `throughput` 可勾选；数据来自 WS `metrics` 事件（`points` 数组逐点入环形缓冲），窗口只保留最近 N 点，历史/回放走 `GET /api/runs/{id}/metrics`（服务端 LTTB）。曲线读写绕过 React 渲染（uPlot 直接操作 DOM）。

## 12. 风险与对策

| 风险 | 对策 |
| --- | --- |
| Transformer / CNN 在 CPU 上慢，演示卡顿 | 小模型 + 小语料；默认步数按设备自适应（FR-11）；GPU 可选；epoch 内限制采样次数 |
| MNIST / CIFAR 下载失败（网络受限） | 手动导入目录 `data/datasets/manual/` + 镜像地址配置；UI 显示缓存状态与放置路径 |
| 探针采样拖慢训练 | 仅采样步挂 hook；通道 / 尺寸双重降采样后量化；实测吞吐前后对比并显示 |
| Windows `spawn` 下子进程导入或序列化问题 | 入口为模块级函数；事件队列只传基本类型；子进程内自行重建模型与 DataLoader |
| 训练崩溃影响服务 | 子进程隔离 + 退出码 / 看门狗检测；失败 run 保留已产生数据供回放 |
| 曲线数据量增长 | 服务端 LTTB 降采样 + 前端环形缓冲；metrics 批量写库 |
| 编辑器搭出跑不通的图 | 保存前强制 dry-run；错误定位到节点并高亮 |
| 磁盘占用失控 | run 删除 + 清理全部历史；容量估算展示；checkpoint 默认只存最优 |
